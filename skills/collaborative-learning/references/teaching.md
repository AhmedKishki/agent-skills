# Teaching and Discussion

## Develop the explanation

- Follow the confirmed topic and subtopic sequence.
- Introduce the current session number, topic, and related arguments briefly.
- Explain in concise, direct, plain language without flattening the reasoning.
- Define necessary terms when introducing them.
- For each argument, make clear the question it addresses, the claim, its grounds,
  the steps connecting those grounds to the claim, and the conclusion's limits.
- Explain how related arguments connect within the current topic.
- Use only the length required to make the argument understandable and complete.
- Include clear source references throughout.

## Keep explanations self-contained

- Never refer the user back to an earlier session for an explanation.
- Restate any earlier definition, premise, or argument needed for the current one.
- Develop the full relevant argument even when it repeats earlier material.
- Do not replace reasoning with phrases such as “as covered in session 2”.
- Apply this rule to answers, saved explanations, and exercise feedback.
- Use saved sessions internally to track progress, not as substitutes for teaching.

## Follow the user's pace

- Present a manageable subtopic or related group, then allow discussion.
- Treat a question or request for clarification as discussion of the current session.
- Answer the actual question before moving on; do not silently skip it.
- Record the interaction and explanation in that same session file.
- Continue with the next pending subtopic when the user asks to proceed.
- Start the next session only after the current topic's planned coverage is complete
  and the user asks to continue, unless the user explicitly requests a different pace.
- Do not equate a new conversation turn with a new session.
- If “next” is ambiguous, clarify the intended next step.

## End a session

- Mark the topic complete when its agreed subtopics have been covered.
- Offer exercise questions as an optional follow-up; do not make them mandatory.
- If requested, ground the questions in the session's material and stated goals.
- Record questions, user answers, and source-grounded feedback in the same file.
- Treat completed coverage as completion of the topic, not proof of user mastery.
