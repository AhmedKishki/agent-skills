# Planning

## Intake

Ask in one message for whatever the request leaves open:

- **Goal.** What the student wants to understand or be able to do at the end, and why. "Learn statistics" can mean passing an exam, reading papers or running A/B tests at work, and each needs a different syllabus, so ask until the goal is concrete.
- **Resources.** Books, files, links or courses the student wants to use.
- **Limits.** A deadline, an exam syllabus or the time they have, if any.

Open the resources as [sources.md](sources.md) describes before you write any question, because the diagnosis and the lessons should follow their scope and terms. If a resource can't be opened, say which one and ask for another copy. If the student brings none, find web sources before you write the diagnosis.

If the student wants to skip the diagnosis, ask two or three questions about their background instead and plan from those answers.

## Diagnosis

The diagnosis produces a map of where the student's understanding holds and where it breaks. The syllabus is planned from this map, so its precision limits the syllabus.

1. **List the strands**: the 3–6 concepts or skills the goal depends on. The resources' table of contents is a good guide.
2. **Ask in rounds.** A round has up to 4 multiple-choice questions and 1–2 free-thought questions, posed as [questions.md](questions.md) describes. Two or three rounds are usually enough.
3. **Enter each strand near the top.** Start near the hardest level the goal needs. Someone asking for advanced material usually holds the basics, so a warm-up question on basics spends a question that could have located the edge. After a correct answer, go up sharply. After a miss, ask below it.
4. **Choose each round from the last one's answers.** A question whose answer you can already predict tells you nothing.
5. **Stop when every strand is bracketed**: a level the student reliably gets right and a level where they miss or don't know.

A single wrong answer can be a slip, a gap or a misconception, and the three look alike. When a miss looks like a misconception, ask one more question around it to see how far it reaches, because a misconception shapes the syllabus more than a gap does.

Don't explain answers during the diagnosis, since an explanation changes the knowledge you are measuring. Tell the student this at the start, and tell them that "I don't know" is a useful answer: guessing hides the edge you are looking for.

## Assessment and syllabus

After the last round, present three things:

1. **Results.** Each diagnostic question with the student's answer, the correct answer, one line on why and the reference for it. A table works well.
2. **Level.** For each strand: solid, shaky or missing, with the answers that show it. List any misconceptions separately.
3. **Syllabus.** A numbered list of lessons. Give each one a title, its type (concept, skill or argument, as [teaching.md](teaching.md) defines them), what it covers in a line or two, the gap or part of the goal it serves, and the sources it draws on, with sections.

Build the syllabus from the level:

- Leave out strands the student holds solidly, and name them in one line so they can ask for them back.
- Order lessons by dependency, so each lesson comes after everything it builds on. Missing foundations therefore come first.
- Repair a misconception in the lesson where it would first cause trouble.
- Give each lesson 1–5 key ideas, which is what one check can cover.
- Leave out topics that don't lead to the goal, however interesting they are.
- Where the student's resources don't cover a lesson, name the web source you would use for it. Approving the syllabus then approves that source.

Write `progress.md` with the syllabus marked `draft`, as [records.md](records.md) describes. Then ask the student to approve or change the syllabus and end your turn. Revise and present it again until they approve. Then mark it `approved` and start lesson 1.

## Revising the syllabus

The student can change the syllabus at any point: add, drop, reorder or split lessons, or change the depth or the goal. Show the revised syllabus with the changes marked, and continue once they approve it. Lessons already done stay done unless the student asks to redo them.

You may propose a change when teaching reveals something the diagnosis missed, such as a missing prerequisite or a strand the student already knows. Give the evidence and wait for approval before changing anything.

Keep existing lesson numbers, because the lesson notes and the log refer to them. Number an inserted lesson with a letter after the lesson it follows (`2a`), and mark a dropped lesson `dropped` instead of deleting its row.

If the student wants to skip a lesson or its check, skip it and mark it `skipped`, because no answer has shown that they understood it. Tell them which later lessons build on it.
