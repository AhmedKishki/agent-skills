# Optional native CLI workflow

The Python CLI is one implementation of the application workflow. It provides source-linked text edits, reviewed language baselines, snapshots, rendering and integrity manifests. It does not decide the applicant's template, document format or professional positioning. Use other suitable tools when agreed; do not claim native verification for artifacts those tools produce.

## Prepare working state

Follow Commands for workspace selection and dependencies. A repository may own clean factual records and professional-profile wording while the native workspace holds the compatible internal representation. Preserve native evidence IDs, source references and policy internally; do not expose an import ledger as the user's professional profile.

`init`, `intake` and `bootstrap` are one-time onboarding operations, not synchronization commands. For later changes, review the maintained sources and update affected native records in place. New or changed claims need source review rather than inherited verification. Follow Freshness for the CLI's calendar-month confirmation and record it only after an actual applicant reply.

## Review the chosen baseline

Choose or author the appropriate HTML/CSS with the applicant. The starter layout is optional. Section selection, order, content emphasis and appearance may be revised while retaining the same underlying facts; keep prior baselines intact.

Run `preview` for the selected language and source files. Source-audit fixed fields and editable text, inspect every rendered page and obtain actual approval before `seal`. A seal records hashes; it cannot prove that the applicant approved the document.

Review each needed English or German variant separately, preserving one shared qualification history. Changes to factual sources, voice or relevant presentation assets require reviewing the affected variant before resealing it.

## Capture and tailor an application

`new --language en|de` captures the chosen approved language baseline and the supplied posting. Retain the returned application path. It does not generate a new CV directly from the maintained facts.

Complete current-job wording and research, then prepare the native plan. Within an existing snapshot, only registered plain-text regions can be patched. The default three-block/15-percent budgets are conservative helper settings, not universal writing rules. If a job needs a different selection, structure or design, review that source and policy as a new baseline and capture a fresh application rather than secretly rewriting an old snapshot or raising its limits.

Run `check`, resolve unsupported claims and inspect the requirement mapping and letter. Build a fresh revision, inspect every page and obtain final applicant review. Keep completed build contents unchanged.

## Verify and retain

`verify` establishes that recorded file hashes match; it does not establish truth, visual quality or consent. `archive` makes a local copy, not a submission. Keep selected documents and useful records in the applicant's agreed folders, without leaving unique data or wording only in native caches.
