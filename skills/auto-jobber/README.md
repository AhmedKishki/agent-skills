# Auto-jobber

A reusable, author-led workflow for maintaining factual data, developing a professional profile, creating CV templates and CVs, and preparing an appropriate CV and cover letter for each supplied job offer. The agent and applicant choose the format, tools, template, information order, emphasis and appearance. Nothing is submitted automatically.

Start with an old CV or lists of qualifications, projects and relevant personal information. Keep facts separate from profile wording and document design. As the applicant adds or corrects data, update the affected profile and working CV naturally; optional material need not appear in every version. Review drafts together rather than treating an import as a finished CV.

For each vacancy, supply the posting and your motivation, examples and desired tone. A cover letter is treated as a personal motivation argument in a human voice, with context and a personal touch, and with room to be distinctive, creative and bold rather than a formal recap of the CV or the posting; the [letter criteria](references/voice.md) guide drafting and review. The agent reuses your existing input, asks for missing personal connections and preserves your perspective without inventing feelings or achievements. Personal wording you enter, such as an interest, an opinion or a closing line, is kept in `personality.json` and used where it fits the opportunity. Letters and statements are [drafted together](references/drafting.md): the agent asks a short questionnaire, one question at a time, each saying what it is for, with its own suggestions labelled; the draft is a plain Markdown file with open points in brackets, and the PDF follows once every point is closed. A factual skeleton requested before motivation is supplied remains labelled incomplete. Later sessions check whether the qualifications need a calendar-month update.

For PhD and other research positions, a [research statement](references/research-statement.md) sets out the applicant's research background, their vision for future work and its fit with the group, following any guide the group publishes. Its default structure and criteria follow the CRISTAL Lab's [Research Statement Guide](https://cristinagarbacea.com/assets/pdf/CRISTAL_Research_Statement_Guide.pdf). The research questions and hypotheses must come from the applicant: the agent marks missing answers as gaps, labels its own linking sentences for review and keeps the draft incomplete until the applicant fills them.

Editable HTML/CSS starter templates and Python utilities are included. They are optional starting points, not a required design or the only way to produce documents. Choose or build a template that serves the applicant and adapt it as needed. Remote fonts/icons and the old Gulp toolchain are not required. Native HTML/PDF helpers support authorized local JPEG/PNG portraits, with Pillow used to validate actual decoding. Images are embedded in standalone output and retained with the reviewed baseline and application snapshots; remote image loads remain forbidden. Photo-free workflows do not require Pillow.

Read [SKILL.md](SKILL.md) for the workflow and reference routing. The command walkthrough covers normalized `intake`, the alternative upstream `bootstrap` import, profile confirmation, CV previews and repeated applications.

The bundled PDF helpers require Python 3, an existing Chrome/Chromium installation and Poppler tools; portrait validation additionally uses Pillow. Agent web access supplies research; the scripts do not generate it. Native helper state defaults to `~/.local/share/auto-jobber`. The applicant chooses where maintained facts, profile wording and documents live, including a private repository when explicitly requested; do not put personal records inside the installed skill.
