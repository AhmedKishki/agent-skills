# Editing

## Purpose

Apply approved changes and direct user edits without losing wording, evidence, IDs, links or downstream consistency.

## Procedure

1. Read the affected live files and preserve a recoverable pre-edit state in version control.
2. Treat direct user edits as user input and route each changed unit to its owner.
3. Apply only the approved substantive change and unavoidable mechanical consequences.
4. Keep source, user-material and argument IDs stable. Never reuse retired IDs.
5. Preserve earlier wording when a meaningful change would break an existing citation or provenance basis; create a new ID when necessary.
6. A changed thesis triggers review of affected arguments, arc units and draft prose.
7. A changed argument claim, qualification or actual synthesis basis triggers review of its argument draft and dependent arc or draft units.
8. An arc change does not alter unordered arguments. It triggers review only of dependent draft prose.
9. Preserve immutable arc, draft and cited-draft versions.
10. Validate wording, evidence, provenance, IDs, links, states and filenames.
11. Check that no active file has accumulated empty/default metadata, broad inventories, duplicated records, migration history or unrelated units; compact before considering a split.
12. Update progress.

## Supersession

Preserve a replaced substantive object in the owning file or an immutable version only when needed for provenance or decision recovery. State its current replacement in plain text. Do not scatter duplicate histories across files.

## Completion

The diff contains no unapproved substantive change and all affected dependants have the correct state.
