# Consent

## Purpose

Apply only the user's explicit decision to the exact substantive object presented.

## Rules

- Approval must identify the proposal or revision unambiguously.
- Silence, lack of objection, “continue” and “next” do not approve.
- A changed object requires a new revision and approval.
- A request for explanation changes no state.
- A rejected argument draft does not remove its argument definition.

## Argument states

### Unstarted

Present the exact argument definition or synthesis-material proposal. Then wait.

### Inputs awaiting approval

If the input set is approved, synthesize the candidate and move to `Candidate awaiting decision`. If inputs change, present the complete revised set and remain here.

### Candidate awaiting decision

If the candidate is approved, save it as `Approved`. If the user requests changes, prepare a new revision. If rejected, preserve the rejected candidate and keep the argument available unless the user removes it separately.

### Blocked

State the precise gap and the one decision or material needed to continue.

### Approved

If its thesis, claim, qualification or actual basis changes, review the argument draft and every dependent arc or draft unit.

## Procedure

1. Identify the exact object addressed by the response.
2. Classify the response as approval, rejection, revision, new material, new direction, structural change or request for explanation.
3. Route it to the object's owner.
4. Apply only the matching change.
5. Update progress.

## Completion

The state reflects only an explicit user decision and the next action is unambiguous.
