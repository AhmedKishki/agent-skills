# Human-editable files

## Purpose

Make every active project file easy for the user to read and edit directly.

## Format

- Use one H1 and descriptive H2 or H3 headings.
- Use normal paragraphs, short labelled fields, bullets, numbered lists and blockquotes.
- Use no Markdown tables.
- Put one argument, decision, source excerpt or draft unit under one heading.
- Keep stable IDs in headings where identity matters.
- State `None` rather than leaving a required field ambiguous.
- Keep process explanation out of article-making material.
- Keep each file small enough to review as one coherent unit. Split an active index or range file before it exceeds 250 lines or 20 KB. When unrelated units make a file cumbersome sooner, use its canonical index-plus-file family rather than adding another section to a monolith.

Working files begin with this note or a shorter equivalent:

> **Editing note:** You may edit this file directly. Keep stable IDs in headings where possible. The assistant will preserve earlier cited or approved material when an edit changes its meaning and will report affected downstream work.

Approved snapshots instead say:

> **Editing note:** This is an approved snapshot. Make proposed changes in the corresponding live file.

## Direct edits

Treat every direct edit as user input. Determine whether it changes wording, thesis, evidence, an argument, synthesis material, the article arc or draft prose. Route it to that owner. Never overwrite it silently.

If an edit changes material already used by provenance, preserve the earlier material under its stable identity, allocate a new identity when needed and identify affected dependants. The user does not manage provenance machinery.

## Metadata limit

Include only metadata needed for identity, source location, authorship, approval or current use. Put current workflow state in the progress file, not throughout the project. Do not retain migration labels after their mechanical purpose is complete.

## Completion

A user can understand and safely edit the file without reading the skill instructions.
