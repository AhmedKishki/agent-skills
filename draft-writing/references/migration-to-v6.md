# Previous-major project migration: v5 → v6

Use for pre-v6 work, active v5-format files, or v6 files failing current schemas or use rules. Ask for staged instructions for older work. Validate conforming v6 files without rewriting them. Preserve established v6.8 dual namespaces.

Migration preserves governing current content and the minimum traceability needed to use it; it does not preserve retracted directions, superseded discussion, or version history. It is resumable and idempotent. Do not alter inputs while reconciling. Transfer every current governing wording, meaning, provenance, use, code, and decision to validated canonical files, then delete the superseded workflow file. Never delete source originals or unresolved inputs. Keep migration state only in the tracker; create no report.

**Omit**: exclude unresolved material from active use but retain it. **Retire**: its governing information is validated elsewhere, so delete its old workflow file under [file-output-standard.md](file-output-standard.md).

## v5 → v6 procedure

1. Read the tracker and inventory candidate files. Establish the active version from completeness, resolved dependencies, and traceable user authority; timestamps do not decide. If more than one candidate remains possible, describe their substantive differences without filenames and ask. Ask about ambiguous source order using full source names.
2. Preserve conforming thesis-and-vision, user-synthesis, and predraft content. Convert a brief without additions. Route governing Q&A once: thesis, metatheory, durable guidance → thesis-and-vision; user content → user-synthesis; selected raw wording → predraft; structure, placement, source role, repetition → arc; gaps → chat. Omit bureaucracy, navigation, superseded answers, and disposable organisation. If an answer is not self-contained without its question, ask for the user's self-contained wording; never copy an AI question into article content. Retire a legacy record only after every routed item is saved and verified readable in its canonical file.
3. Recover codes from every active or unresolved legacy source. Set **Next source code** to the first code after the highest traceably used; assign it in legacy-tracker order and increment after each assignment. Ask if order is ambiguous; never alphabetise, knowingly reuse, or reassign.
4. Convert each uncoded excerpt file to a map, preserving identity, order, source wording, locators, qualifications, provenance, and use. Convert broad quotations into one-claim/topic fragments by deletion and **[…]** only, retaining enough Human context to preserve meaning. Record old-to-new IDs in a temporary **Migration aliases** section of that map; remove it after every dependent resolves. If a cut or split is uncertain, keep the legacy input unresolved and ask. Build the source path from the original or mark **Unresolved**. Apply established Framework roles and record Article roles separately; ask on unknown roles. Continue historical namespaces and never combine non-identical items.
5. Retire the evidence map only after every governing item is resolved or represented canonically. Until then list it in the tracker and ask. Route user cross-source synthesis to user-synthesis. Preserve a Mixed/AI relation or placement only when its inputs and use are traceable; keep dated AI gap suggestions unsupported.
6. Convert a flat arc to current section, argument, and paragraph fields, preserving established order, functions, and placements. Add only established source contributions; ask about missing boundaries, claims, handoffs, roles, or fit.
7. Stamp every passage. Preserve known origin and calculate percentages only from traceable spans. Map only exact, scoped uses; never upgrade generic approval. Assistant synthesis stays terminal Mixed with original Human inputs. Mark uncertainty **Unresolved**, omit dependents, and ask.
8. Replace predraft bases with canonical files or, for chat-origin AI wording, a dated exchange and original Human inputs. An AI gap suggestion also records checked source coverage. Keep wording unchanged. Retain each fidelity report until every governing finding is resolved or represented canonically, then retire it. Omit drafts until dependencies and appendix migrate, then create a new draft and changelog.
9. After each migrated file, create a tracker naming the mode and every remaining governing legacy or reconciliation input. Use the plain version label only when none remain.

Recover the sole predrafting argument or ask with a suggestion; never infer or batch. Save and track immediately. Reopen completed migration only for a new governing legacy file or framework source, user correction, or invalidating audit finding. Never remigrate unaffected files.
