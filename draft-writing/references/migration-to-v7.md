# Previous-schema project migration: v6 → v7

Use for schema-v6 work or v7 files failing current schemas or use rules. Work older than v6 must first migrate with a release that supports its immediately following schema. Validate conforming v7 files without rewriting them.

Migration preserves governing current content and the minimum traceability needed to use it; it does not preserve retracted directions, superseded discussion, or version history. It is resumable and idempotent. Do not alter inputs while reconciling. Transfer every current governing wording, meaning, provenance, use, code, and decision to validated canonical files, then follow the [removal-impact protocol](file-output-standard.md) before retiring a superseded workflow file. Never delete source originals or unresolved inputs. Keep migration state only in the tracker; the predraft report is a current workflow output, not a migration report.

**Omit** means exclude unresolved material from active use but retain it. **Retire** means its governing information is validated elsewhere, so its old workflow file may be deleted under [file-output-standard.md](file-output-standard.md). Every omission or retirement below remains subject to the shared removal-impact protocol.

A v6 project already declared complete may remain complete unchanged. Apply v7 migration only when the user explicitly requests it or reopens the project. Never represent a v6 approval as authority for a new v7 global refinement.

## Reconciliation rules

Keep conforming thesis-and-vision, user-synthesis, source maps, source codes/namespaces, index entries, exact predraft wording, provenance, and explicit uses. Preserve established v6.8 dual namespaces. Rebuild a missing source path only from an accessible original; mark unknown roles, bases, or dependencies **Unresolved** and ask.

Every v6 assistant synthesis remains terminal Mixed regardless of its historical label. It is usable only when its original Human 100% bases are traceable and it satisfies the current white-box record or the legacy-compatibility procedure below. Otherwise retain its containing file as a tracked non-active reconciliation input, omit its dependents, disclose the exact missing basis or trace, and ask; user selection never cures the failure.

A legacy **Mixed reductive synthesis** label is historical, not proof of white box compliance; never rename it in place or infer a record from the candidate alone. Reopen the original Human bases and validate the target, closed COPY/INFLECT/ORDER/DELETE operations, quotations, final white box record, and Human basis for every adjacency and cut.

- If it passes, preserve its exact wording, origin, historical method, selection, and use. Through normal candidate, removal-impact, and replacement handling, retain the final white box record and use **Method: legacy reductive synthesis · white-box compatibility verified** in its canonical local stamp.
- If it fails, retain the containing file as a tracked non-active reconciliation input, identify the passage in its role/state and **Now/Next**, omit its dependents, disclose the exact missing basis or trace, and ask.

User selection never cures a fidelity failure.

## v6 → v7 procedure

1. Read the tracker and inventory every active or unresolved workflow file. Establish the governing version from completeness, resolved dependencies, and traceable user authority; timestamps do not decide. If more than one candidate remains possible, describe substantive differences without filenames and ask.
2. Replace the v6 tracker fields with the v7 [activity tracker](activity-tracker.md). Set **Focus** to **resume-or-migrate** while reconciling; translate evidence from the old stage into **State**, **Now**, and **Next**, but never infer the user's next content function or treat a stage label/approval as content/use authority. Append **migration v6 → v7** and list every remaining input until reconciliation completes; then use **None—awaiting user's function choice** unless the user already called another function.
3. Preserve every conforming thesis, source, map, index, and user-synthesis item without changing its role or use. A framework change reopens thesis-and-vision and every affected dependent. Continue source/item codes; never renumber, reuse, or combine non-identical items.
4. Convert the article arc without inventing fields. Preserve established global/local order, questions, functions, boundaries, handoffs, source contributions, placements, and repetition homes. Convert **Include unchanged** to **Use as raw material** with authority for unchanged placement only; it grants no consolidation, reordering, deletion, refinement, or new wording. Preserve authorised **Omit**; convert **Undecided** or missing emphasis/sole-home fields to **Undecided** and ask. Obtain explicit approval of the complete v7 arc.
5. Preserve each active predraft passage unchanged with its basis, provenance, alternatives, and **Predraft raw material** use. A v6 passage selection or arc approval is not approval of the complete raw-material set. Resolve every passage's v7 arc disposition, then show and obtain explicit approval of the complete predraft for whole-predraft review.
6. **Review-predraft** remains unavailable until the v7 arc and complete predraft are mutually consistent and approved, every active source role is resolved, and the index is current. Do not run it merely because those inputs become ready; wait until the user calls it. Infer no fix or exception from a v6 draft, changelog, approval, or prior fidelity report; when called, resolve every finding through current Q&A and exact authority.
7. Preserve an existing v6 draft's wording, provenance, status, and approvals. If it is not complete, retain its containing draft/changelog files as tracked non-active reconciliation inputs until a report-governed v7 draft validates; do not silently redraft or delete them. A completed v6 draft remains historical completed output unless reopened. An old exact-copy draft may help identify prior authority but never replaces the v7 report gate.
8. Hand-off documents, source exports, and user exports are retired noncanonical request artifacts. Ensure their sole resume state and governing content exist in current canonical owners before disclosed retirement. Never use an old export to replace a missing source map, index, or canonical file.
9. Reconcile an older **Active filename** table to the current **Tracked filename** working set. Track every non-active file still needed for migration/reconciliation with an accurate role/state and self-contained **Now/Next**. The full-export helper's legacy-header support does not prove completeness.
10. After each migrated canonical file, save a tracker naming every remaining reconciliation input. Use the plain schema-v7 workflow line only when none remains. Retire predecessors only after their successors and dependents validate under the candidate test.

Recover one current local-predrafting argument or one open predraft-report finding; ask on ambiguity and never batch inferred decisions. Reopen completed migration only for a new governing v6 input, user correction, or invalidating audit finding. Never remigrate unaffected work.
